# Cam Proctor — 웹캠 2대 부정행위 감지 (프로토타입)

pAIr 본 앱과 별개로 만든 카메라 감독 시스템입니다. **영상은 서버로 보내지 않습니다.** 두 카메라 모두 브라우저 안에서 MediaPipe로 분석하고, 경고가 확정된 순간의 이벤트와 사진 1장만 서버로 보냅니다.

| 카메라 | 실행 위치 | 감지 항목 |
| --- | --- | --- |
| 노트북 정면 캠 | PC 웹 (`/`) | 얼굴 없음 · 여러 얼굴 · 고개 돌림/들기 · 고개 오래 숙임 · 시선 이탈 · 몸통 이동 · 몸 돌림/멀어짐 |
| 휴대폰 보조 캠 | 폰 웹 (`/?role=phone`, QR로 접속) | 손 이탈 · 손 위치 이탈 · 팔 큰 움직임 · 휴대폰 · 추가 화면(켜짐 여부) · 책 · 폰 화면 이탈/연결 끊김 |

## 실행

```bash
npm install
npm run dev
```

1. PC에서 `https://localhost:5174` 접속. 인증서 경고는 "계속"으로 넘어갑니다 (자체 서명).
2. **감독 시작** → 3초 동안 정면을 보면 기준 자세를 잡고 감시를 시작합니다.
3. 휴대폰을 **같은 와이파이**에 연결하고 PC 화면의 QR을 찍습니다. 인증서 경고를 넘긴 뒤 **보조 캠 시작** → 두 손을 키보드에 올린 채 3초 기다리면 감시를 시작합니다.
4. 폰 경고는 PC 화면의 경고 기록에 함께 뜹니다.

폰이 안 붙으면 Windows 방화벽에서 Node.js의 사설 네트워크 수신을 허용하세요.
PC 단독으로 볼 때는 `npm run dev -- --mode http` (HTTP, localhost 전용)도 됩니다.

## 시험 전 환경 점검

감독 시작을 누르면 먼저 점검을 하고, 실패 항목이 없어야 감독으로 넘어갑니다. 주의(warn) 항목은 기록만 남깁니다. 결과는 `data/checks.jsonl`, 점검 사진은 `data/snapshots/`에 저장됩니다.

| 위치 | 항목 | 방법 |
| --- | --- | --- |
| PC | 브라우저·자동화 | Chromium 여부, `navigator.webdriver` |
| PC | 원격 접속·가상 머신 | WebGL 렌더러 이름 (Basic Render Driver, SwiftShader 등 → 주의, 약한 신호) |
| PC | 모니터 | `getScreenDetails()`로 대수 → 안 되면 `screen.isExtended` |
| PC | 가상 카메라 | 카메라 이름 (OBS, ManyCam, DroidCam 등 → 실패) |
| PC | 이어폰 연결·소음 | 마이크 권한으로 오디오 장치 이름 확인 (AirPods, Buds, 헤드셋 → 실패), 2초 소음 측정 |
| PC | 조명·얼굴 위치·혼자 | 밝기·역광, 얼굴 크기·위치, 얼굴 수가 1.5초 동안 정상 |
| PC | 양쪽 귀·손목 | 고개를 좌우로 돌린 순간, 두 손을 보인 순간을 촬영 |
| 폰 | 조명 | 어두우면 손전등 자동 켜기 (안드로이드 크롬) |
| 폰 | 방 360도 | 자이로로 12방향 중 10방향 이상 확인(아이폰은 권한 요청), 장면이 바뀔 때마다 사진. 고해상도(1280x720) 프레임을 전체+2x2 타일로 나눠 감지 → 사람·휴대폰·책·화면 |
| 폰 | 책상 위 | 6초 동안 내려다보며 촬영, 같은 타일 감지 |
| PC | 정밀 분석 | 점검 사진 전부를 OWL-ViT(글로 찾을 물체를 지정하는 모델)로 다시 확인: 메모지, 필기된 종이, 이어폰, 스마트워치, 손에 쓴 글씨, 태블릿 등. **자동 판정이 아니라 "검토 필요" 표시** |

정밀 분석 모델은 처음 한 번 약 150MB를 받고(브라우저 캐시), PC에서 사진 한 장에 약 3초 걸립니다.

### 남는 한계

- 웹에서는 PC의 다른 프로그램(원격 제어 앱 등)을 직접 볼 수 없습니다. 렌더러 이름은 약한 신호일 뿐이고, 확실하게 막으려면 Safe Exam Browser 같은 잠금 브라우저가 필요합니다.
- 화면 복제로 연결한 모니터는 API로 안 잡히고, 휴대폰 360도 스캔에 화면이 보이는지로만 확인합니다.
- 휴대폰에 연결된 이어폰, 마이크 권한 없이 연결된 이어폰은 장치 이름으로 못 잡고, 귀 사진 분석에 맡깁니다.
- OWL-ViT는 오탐이 있어서 감독관이 사진으로 확인하는 용도로만 씁니다.

## 판정 방식

- 시작할 때 3초 보정 → 각 값의 **중앙값**을 기준 자세로 잡고, 이후 기준과의 차이로 판정 (사람마다 다른 카메라 각도·자세 보정).
- 이상 상태가 **일정 시간 계속돼야** 경고 (`src/rules/RuleEngine.ts`). 한 프레임 튀는 오탐을 막고, 0.4초 이내로 잠깐 끊긴 감지는 같은 구간으로 봅니다. 규칙마다 쿨다운이 있습니다.
- 기준값은 `src/rules/pcRules.ts`의 `PC_THRESHOLDS`·`PC_RULES`, `src/rules/phoneRules.ts`의 `PHONE_THRESHOLDS`·`PHONE_RULES`에 모여 있습니다. PC 화면 아래 표에 실시간 수치와 기준값이 같이 나와서 오탐률 튜닝할 때 쓸 수 있습니다.

## 서버 (`server/relay.ts`)

Vite 개발 서버에 붙는 WebSocket 릴레이입니다.

- `/ws`: PC가 세션을 만들고, 폰은 QR 속 세션 ID와 토큰으로 붙습니다. 경고의 출처(pc/phone)는 서버가 연결 역할로 정합니다.
- 사진은 `data/snapshots/<세션>/`, 이벤트는 `data/events.jsonl`에 저장합니다. 보관 기간(`SNAPSHOT_RETENTION_HOURS`, 기본 168시간)이 지나면 사진을 지웁니다.
- 폰 연결이 끊기거나 6초 이상 신호가 없으면 서버가 직접 경고를 만듭니다.
- `GET /api/sessions/:id/events`: 세션 경고 목록.

PC 화면의 **전송량** 패널에서 실제로 보낸 바이트와 영상 스트리밍(1.5Mbps 가정)을 비교합니다.
