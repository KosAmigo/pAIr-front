## 항목별 메모

- **3:** 등급이 바뀔 만큼 흔들린 샘플은 없음. 판정 기준 문장 보완 후 재측정
- **7:** `--init --network none --memory 512m --cpus 1 --pids-limit 128 --read-only --cap-drop ALL`. 무한 루프, 메모리, 인터넷, 스레드, 시스템 파일 쓰기 차단. 고친 것: 시간 초과 후 남는 프로세스 정리, 좀비 방지(`--init`)
- **8:** 작업 폴더를 tar로 저장/복원. 체크포인트 1개 20KB
- **9:** 폴더 읽기 전용, 지정 파일만 쓰기 허용. 편집기는 직접 덮어쓰기로 저장, 롤백은 root 컨테이너로 복원. 과제 문구 "테스트 추가"는 기존 파일에 추가로 안내
- **10:** CodeMirror + JDK 컴파일러 API로 오류 밑줄, 자동 완성, 정의로 이동. 30명 동시 입력 시 CPU 1개 1.4초, 2개 0.7초. 언어 서버는 1명당 250MB라 제외
- **11:** Tika도 20/20이지만 내부에서 PDFBox를 쓰므로 PDFBox 하나로 충분. PDFBox의 위치 정렬을 켜면 2단 편집에서 좌우 단 줄이 섞임. 줄바꿈이 단어 중간에 생기므로 조각에서는 줄을 이어 붙임
- **12:** 3-large는 1위 적중(14 vs 10)만 좋고 비용이 약 6.5배. 1536차원으로 줄여도 같은 결과
- **13:** 고정 800자 19/20, 400자 19/20, 200자 13/20. 쪽이 짧은 문서라 쪽 단위가 가장 단순하고 정확. 숫자 표는 기존 실험대로 통째로
- **14:** 과제 1,000개 × 조각 50개. HNSW는 가까운 40개를 먼저 고른 뒤 과제로 걸러서 결과가 0개, 반복 스캔을 켜도 재현율 40%(무작위 벡터 기준). 인덱스 391MB, 생성 6분 47초. 검색은 항상 과제 안에서만 하므로 B-tree로 수십 개만 꺼내 전부 비교
- **15:** 비개발 샘플 2개에 PDF 4개를 자료로 더해 통째로/RAG 각 3회 채점(`pair.judge.reference-docs`). 자료 글자 9,469자 → 2,302자(AI 답 붙인 응시), 5,259자(모범 응시). 채점 비용 $0.152 → $0.118(−23%). 총점 평균: 붙인 응시 60.7 → 63.7, 모범 94 → 94. 수치가 많은 제출물은 검색 문장이 많아 조각을 많이 가져와 절감이 작음. 문서가 늘수록 절감이 커지므로 실제 과제 규모에서 다시 측정

## 서버 구조

```
브라우저 → AWS EC2 (무료): Spring Boot + PostgreSQL (회원, 응시 기록, AI, 채점)
                │ 내부 API (토큰, AWS IP만 허용)
                ▼
           Oracle Cloud (무료 ARM): 실행 서버 (컨테이너, 테스트 실행, 롤백, javac 분석)
```

- 무거운 실행은 Oracle, 응시자 코드는 DB/API 키와 다른 서버에서 실행
- 응시자 배정: 응시 시작 때 가장 한가한 실행 서버를 DB에 기록하고 끝까지 그 서버만 씀. 1대로 시작해 늘면 추가
- 대비: 실행 서버 장애 시 실행 일시 중지와 시간 보정. 제출 파일은 AWS에 보관
