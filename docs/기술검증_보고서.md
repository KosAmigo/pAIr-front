## 5. 응답 속도

- 어시스턴트: 실제 응시 35턴, 평균 7.6초, 중앙값 5.0초, 최대 21.8초
- 채점: 35건에 3분 51초 (동시 4건) → 1건 약 26초
- 참고: 최대 21.8초인 긴 답변도 있으나 스트리밍으로 첫 글자가 바로 보임

## 7. 코드 실행 격리

- 설정: `--init --network none --memory 512m --cpus 1 --pids-limit 128 --read-only --cap-drop ALL`, 일반 사용자, `/tmp` 64MB, 시간 제한 30초
- 실행: `poc/sandbox/isolation-test.sh`

| 나쁜 코드 | 결과 | 판정 |
|---|---|---|
| 무한 루프 | 30초에 강제 종료, 남은 프로세스 정리됨 | ✅ |
| 메모리 무한 할당 | 512MB에서 강제 종료(Killed) | ✅ |
| 외부 인터넷 접속 | UnknownHostException | ✅ |
| 스레드 무한 생성 | 약 100개에서 생성 실패 | ✅ |
| 시스템 파일 쓰기 | Read-only file system | ✅ |
| 디스크 채우기 | `/tmp`는 63MB에서 막힘, 작업 폴더는 1GB까지 써짐 | ⚠️ |

- 모든 경우에 컨테이너는 계속 살아 있음
- 실제 과제 테스트: 혼자 7초, 10건 동시 약 20초 (모두 통과)
- 검증 중 발견해 고친 것: 시간 초과 때 `timeout`이 java를 못 끊어 계속 남음 → 실행마다 남은 프로세스 정리. 끊긴 프로세스가 좀비로 쌓임 → `--init` 추가
- 보완: 작업 폴더 용량 제한 필요 (볼륨 용량 제한 또는 크기 검사)

## 8. 시점 롤백 후 이어 풀기

- 방법: 작업 폴더를 tar로 저장, 롤백하면 비우고 풀기. 새 분기는 새 컨테이너에 복원
- 실행: `poc/sandbox/checkpoint-test.sh`

| 확인 | 결과 | 판정 |
|---|---|---|
| 파일 복원 | 해시 일치, 이후 추가한 파일 없어짐, 삭제한 파일 돌아옴 | ✅ |
| 롤백 후 이어 풀기 | 복원한 상태에서 컴파일, 테스트 정상 | ✅ |
| 기존 분기 보존 | 새 분기를 띄워도 원래 분기와 저장본이 그대로 | ✅ |
| 속도 | 저장 0.4초, 복원 0.8초 | ✅ |
| 용량 | 체크포인트 1개 20KB (40개 저장해도 약 0.8MB) | ✅ |

- 분기별 채점은 채점이 분기별 파일과 대화를 받으면 되므로 기존 채점 코드를 그대로 쓸 수 있음

## 9. 지정 파일만 수정

- 방법: 서버가 작업 폴더를 준비할 때 폴더와 파일 주인을 root로, 폴더는 읽기 전용(555), 수정 가능한 파일만 쓰기 허용(666). 응시자 컨테이너는 일반 사용자 + 권한 없음이라 규칙을 바꿀 수 없음
- 실행: `poc/sandbox/file-rule-test.sh`

| 시도 | 결과 |
|---|---|
| 지정 파일 수정, 테스트 파일에 테스트 추가 | 허용 ✅ |
| 읽기 전용 파일 수정, 새 파일, 새 폴더, 삭제, 이름 변경, 권한 변경 | 차단 ✅ |
| 응시자 코드(Java)가 파일 생성 | 차단 (AccessDeniedException) ✅ |
| 컴파일과 테스트 실행 | 허용 ✅ (결과물은 `/tmp`에 씀) |

- 주의
  - 편집기 저장은 임시 파일을 만든 뒤 바꿔치기하는 방식이면 막힘 → 파일 내용을 직접 덮어쓰는 방식으로 저장
  - 롤백 복원은 규칙 밖에서 해야 하므로 준비용(root) 컨테이너로 처리
  - 현재 과제의 "JUnit 테스트 1개 이상 추가"는 기존 테스트 파일에 추가하는 것으로 안내 필요. AI 수정 제안의 새 파일 만들기도 막아야 함

## 10. IDE 기능 (javac API)

- 방법: 편집기는 CodeMirror 그대로, 오류 밑줄과 자동 완성은 서버에서 JDK 컴파일러 API로 분석. 별도 프로세스 없이 요청마다 잠깐 분석
- 실행: `poc/javac-api/JavacAssist.java` (CPU 1~2개, 메모리 1GB, 힙 256MB 컨테이너에서 측정)
- 언어 서버(Eclipse JDT LS)를 쓰지 않는 이유: 응시자 1명당 약 250MB를 계속 차지하고, 여러 명이 하나를 공유하면 응시자끼리 자동 완성이 섞임

| 기능 | 결과 | 1명 응답 |
|---|---|---|
| 오류 밑줄 | 타입 오류, 문법 오류 위치와 메시지 | 평균 82ms |
| 자동 완성 | `s.` → `Stock` 메서드, `s.de` → `decrease` | 평균 97ms |
| 정의로 이동 | `Stock` → `Stock.java` 5줄 | 평균 71ms |
| 메모리 | 1명 힙 최고 28MB, 30명 동시 237MB | - |

| 동시 입력 (모두 0.5초마다 오류+자동 완성, 최악 조건) | CPU 1개 | CPU 2개 |
|---|---|---|
| 10명 | 평균 0.5초 | 평균 0.2초 |
| 30명 | 평균 1.4초 | 평균 0.7초 |

- 타이핑을 멈추고 0.3~0.5초 뒤 분석하면 실시간 밑줄처럼 보임
- 1회 분석에 CPU 약 0.1초. 실제로는 계속 입력하지 않으므로 CPU 1개당 약 30명 수준으로 추정
- 한계: 이름 일괄 변경, 자동 import 같은 리팩터링 기능은 없음

## 서버 구조

```
브라우저 → AWS EC2 (무료): Spring Boot(회원, 응시 기록, AI 어시스턴트, 채점) + PostgreSQL
                │ 내부 API (토큰 인증, AWS IP만 허용)
                ▼
           Oracle Cloud (무료 ARM): 실행 서버(컨테이너, 파일, 테스트 실행, 롤백, javac 분석)
```

- 무거운 일(코드 실행, 분석)은 큰 무료 서버로, 가벼운 일(AI, 채점은 외부 API)은 작은 서버로 나눔
- 응시자 코드가 DB, API 키가 있는 서버와 다른 서버에서 실행되어 더 안전함
- 대비: 실행 서버가 멈추면 기존 `CodeRunner`(별도 JVM)로 실행. 제출 때 최종 파일을 AWS로 가져와 보관

## 결론

Spring AI 이중 채점은 연동, 출력 형식, 비용, 속도 면에서 바로 쓸 수 있다. 채점 일관성은 판정 기준 문장을 보완한 뒤 다시 측정한다. Docker 격리, 롤백, 지정 파일만 수정, javac API IDE 기능은 PoC로 동작을 확인했다. 실행은 AWS와 분리한 Oracle 실행 서버에서 하고, 작업 폴더 용량 제한을 보완한다.
