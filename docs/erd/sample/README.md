# ERD 샘플 데이터 검증 (2026-11-16)

ERD 확정 전에 실제 데이터를 넣어 구조를 검증했다.

## 실행
```bash
python docs/erd/sample/make_sample.py   # csv/*.csv 생성
python docs/erd/sample/embed.py         # csv/document_chunks.csv (OpenAI text-embedding-3-small, 1536차원)
bash docs/erd/sample/load.sh            # eXERD용 Docker DB(pair-erd-pg)에 적재
docker exec -i pair-erd-pg psql -U pair -d pair < docs/erd/sample/verify.sql
```

## 데이터
- 실제: 과제 2개와 파일, 샘플 응시 7건(대화, 작업 기록, 작업 파일, 후속 답변), 6개 역량 채점 결과 7건(체크 결과, 모델별 판정, 근거), 프롬프트 버전 2개
- 예시로 만듦: 회사 1개, 회원 4명(관리자, 응시자 2명, 기업 담당자 1명), 비개발 객관식·단답형 문항과 답, 대화 첨부 2건, 체크포인트 1건과 거기서 롤백한 응시 1건, 실전 시험 회차 1개(과제 2개, 초대 3명, 입장 2명 = 개발 응시 4·5번을 실전으로 가정 + 응시자A가 비개발 과제를 푸는 중인 응시 1건, 실전은 로그인 없이 보므로 회원 없음)와 감독 동의 2건·감독 이벤트 5건(담당자 판단 2건: 문제 없음 1, 부정 의심 1)
- 비개발 자료 2개(설문 요약, 매출 CSV)는 PDF라고 가정해 페이지 5장, 조각 7개로 나눔
- 34개 테이블 약 1,300행

## 결과
| 검증 | 결과 |
|---|---|
| 외래 키 순서로 전체 적재 | 오류 없음 |
| 잘못된 데이터 차단 (외부 업로드 첨부, 원본 없는 과제 자료 첨부, 중복 턴 번호, 없는 응시, 같은 문항 두 번 답, 같은 코드·직군 체크, 없는 페이지의 조각, 차원이 다른 벡터) | 8종 모두 차단 |
| 감점 합으로 계산한 총점 vs 실제 리포트 총점 | 7/7 일치 |
| 활용 쿼리 (근거 문서 2개 미만 문항, 첨부 vs 정답 근거, 판정 엇갈림 체크, 롤백 횟수, jsonb 조회, 토큰 합계) | 모두 의도대로 동작 |
| 한국어 의미 검색 (질문 5개) | 정답 조각이 1위 4개, 3위 안 5개 |

## 발견한 것
- **번호를 직접 넣어 적재하면 자동 번호(시퀀스)를 맞춰야 한다.** 안 하면 다음 INSERT 가 1번과 겹친다. `load.sh` 에 반영했다.
- **attempts ↔ checkpoints 는 서로를 가리킨다.** 적재할 때 롤백 출발점(forked_from_checkpoint_id)은 체크포인트를 넣은 뒤에 채워야 한다.
- **검색은 상위 3개를 쓰는 게 안전하다.** "가격 때문에 떠난 고객은…" 질문은 정답 조각(유사도 0.429)과 다른 조각(0.436)의 점수 차가 매우 작았다.
- **숫자 표(CSV)는 RAG 보다 표 전체를 넘기는 게 낫다.** 행이 비슷비슷해 조각끼리 점수 차가 작다. 표가 작으면 통째로 채점 모델에 넘기고, RAG 는 글 문서에 쓰는 것을 권장한다.

## 외래 키 인덱스 (2026-11-16)
- **PostgreSQL 은 외래 키에 인덱스를 자동으로 만들지 않는다.** 리포트 조회에서 `judge_verdicts` 를 통째로 훑는 것을 확인하고, 자주 조회하는 외래 키에 인덱스를 추가했다(`pair_schema.sql` 인덱스 절). 지금 데이터 양에선 PostgreSQL 이 통째로 읽는 쪽을 고를 수 있어, 인덱스를 타는지는 순차 읽기를 끄고 확인했다.
- **Windows Git Bash 에서 `docker exec ... /sample` 경로가 `C:/Program Files/Git/sample` 로 바뀐다.** `load.sh` 에 `MSYS_NO_PATHCONV=1` 을 넣어 고쳤다.

## 단답형 정답 대리키 (2026-11-17)

## 체크포인트 파일 대리키 (2026-11-18)

## 실전 회차에 과제 여러 개 (2026-11-18)
회차 하나에 과제를 여러 개 걸 수 있게 바꿨다. 시간은 회차 전체로 본다.
- exam_session_tasks(회차↔과제, 순서) 추가, exam_sessions.task_id 삭제
- 응시가 대상자를 가리킨다(attempts.participant_id, 실전만). (대상자, 과제) UNIQUE 로 과제마다 응시 1건. exam_participants.attempt_id 삭제
- 감독 동의는 대상자 단위(proctor_consents PK = participant_id)로 회차당 1번
- 샘플: 회차 과제 2개, 응시자A가 비개발 과제를 푸는 중인 실전 응시 1건 추가
- 5배 복제 검증은 같은 데이터를 곱한 것이라 의미가 적어 `scale.py` 와 함께 지웠다

| 검증 | 결과 |
|---|---|
| 총점 7건 | 리포트와 같음 (96, 96, 93, 68, 45, 96, 60) |
| 정합성 15종 (새로: 실전 응시 과제가 회차 과제에 없음, 입장 기록 없음, 시험 시간 밖 시작, 감독 이벤트가 실전 응시가 아님) | 모두 0건 |
| 잘못된 데이터 차단 34종 (새로: 같은 회차 같은 과제·같은 순서, 같은 대상자 같은 과제 두 번, 대상자 없는 실전 응시, 대상자가 연결된 자가진단) | 모두 차단 |

- "실전 응시 과제는 회차 과제 중 하나"는 테이블을 건너는 조건이라 서비스 코드에서 지키고 `verify.sql` 3절로 점검한다.

## 입장 코드 삭제 (2026-11-18)
실전 시험은 메일로 받은 개인별 입장 링크로만 들어오게 했다. exam_sessions.entry_code 를 지우고, 검증 SQL의 "같은 입장 코드 회차" 차단을 "같은 입장 링크 토큰" 차단으로 바꿨다.
