> 작성일: 2026-11-12
> 상태: 2026-11-12 채점 코드에 반영함 (채점 기준은 [채점_기준표.md](채점_기준표.md)가 기준)
> 기준 문서: [채점_기준표.md](채점_기준표.md)

## 1. 배경

국내외 AI 역량 평가 15곳을 조사했다.
- **재현성**은 프로그래머스만 쓰는 항목이다. 다른 곳은 같은 지시로 같은 결과가 나오는지를 따로 재지 않는다. 우리 흔들림 테스트에서도 R1(다시 실행)은 같은 응시를 다시 채점할 때 0~8점으로 흔들려, 응시자 능력보다 모델의 무작위성을 재는 면이 컸다. 그래서 항목을 뺀다.
- 대신 여러 곳에서 공통으로 보는데 pAIr에 따로 없는 두 가지를 넣는다.

| 새 항목 | 비슷한 기준을 쓰는 곳 |
|---|---|
| 문제 분해력 | Codility(문제 분해, 모호한 문제 쪼개기), 조코딩AX APTA(문제 정의, 접근 설계), Atlassian(범위 정하기), TestGorilla(시스템 사고와 문제 해결), 면접 채점 공통 기준(과제 분해) |
| 위임 판단력 | Anthropic AI Fluency(위임), Bryq(AI 작업 전략), Codility(AI에 맡길지 직접 할지 판단), TestGorilla(언제 AI를 쓰고 언제 안 쓸지), HackerRank(AI를 판단의 대체물이 아니라 보조로 쓰는지) |

조사 후보였던 보안 의식, 설명 책임은 이번 초안에서 뺐다.

## 3. 항목 정의

### 문제 분해력
**정의:** 큰 문제를 AI가 다루고 사람이 확인하기 쉬운 단위로 나누고, 순서를 세워 차례로 해결하는 능력이다.
**보는 것:** 세 가지 축으로 본다.
- 크기: 한 번에 맡기는 덩어리가 중간 결과를 확인할 수 있을 만큼 적당한가 (너무 크면 K1)
- 순서: 원인 파악, 해결, 확인처럼 앞 단계가 끝난 뒤에 다음 단계를 요청하는가 (거꾸로면 K2)
- 효율: 확인할 것도 없는데 쓸데없이 잘게 쪼개지 않는가 (너무 작으면 K3)

### 위임 판단력
**정의:** 어떤 일을 AI에게 맡기고 어떤 일을 직접 할지 가려내는 능력이다.
**보는 것:** AI가 잘하는 일(초안, 반복 코드, 자료 요약)은 맡기고, 사람이 책임져야 하는 판단(근본 원인 결정, 최종 결론과 추천안)은 직접 내렸는지. 직접 보면 바로 아는 일을 AI에게 묻느라 시간을 쓰지 않았는지.

## 4. 감점표 초안

기존 규칙(배점에서 감점, 판정 체크는 두 모델 평균, 근거 턴 필수, AI 미사용이면 0점)을 그대로 따른다. 통제력, 결과 도출력, 성과 잠재력은 [채점_기준표.md](채점_기준표.md)와 같다.

### AI 활용력 (20점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| U0 | AI에게 한 번도 질문하지 않음 (이 항목 0점) | -20 | 자동 |
| U1 | 첫 질문에서 무엇을 하려는지(목표)를 밝히지 않음 | -4 | 판정 |
| U2 | 필요한 코드, 로그, 자료를 붙이지 않아 AI가 추측해서 답하게 함 | -5 | 판정 |
| U3 | 대부분의 질문에서 원하는 출력 형식이나 범위를 정하지 않음 | -3 | 판정 |
| U5 | 막혔을 때 거의 같은 질문을 3번 이상 반복하고 전략을 바꾸지 않음 | -3 | 판정 |
| U6 | AI 답변을 받은 뒤 이어서 확인하거나 좁혀 묻는 질문이 없음 | -3 | 판정 |
| U7 | 핵심 지시가 앞 대화 없이는 뜻이 통하지 않음 ("그거 다시 해줘" 등, 기존 재현성 R2) | -2 | 판정 |

- U4는 문제 분해력 K1로 옮겼다. 코드 번호는 기존 기록과 헷갈리지 않게 비워 둔다.

### 문제 분해력 (10점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| K0 | AI를 쓰지 않아 AI에게 일을 나눠 맡기는 모습을 볼 수 없음 (이 항목 0점) | -10 | 자동 |
| K1 | **너무 큰 덩어리:** 앞 결과에 기대는 여러 단계를 한 요청으로 맡겨, 중간 결과를 확인하지 못함 (기존 U4를 옮겨 넓힘) | -5 | 판정 |
| K2 | **순서 거꾸로:** 앞 단계가 끝나기 전에 뒤 단계를 요청함 (원인 확인 전에 수정, 자료 확인 전에 결론, 실패하기 전에 "알아서 해결") | -3 | 판정 |
| K3 | **너무 잘게 쪼갬:** 한 번에 해도 되는 단순한 일을 여러 턴으로 나눠, 확인할 것도 없이 턴만 늘림 | -2 | 판정 |

- 세 체크는 서로 다른 축을 본다. K1과 K3은 "한 번에 맡기는 크기"의 양 끝(너무 큼, 너무 작음)이라 한 응시가 둘 다 걸리기 어렵다. K2는 크기와 관계없이 순서만 본다.
- 처음 초안의 K2(한 요청에 여러 일을 섞음)는 K1과 같은 행동을 두 번 감점해서 K1에 합쳤다. 서로 관계없는 간단한 일을 함께 요청하는 것(예: "오타 고치고 제목도 바꿔 줘")은 감점하지 않는다.
- K3은 효율을 보는 자리다. 확인 지점에서 나눈 것은 걸리지 않는다.
- 개발 예: "교착 원인 찾아서 고치고 테스트도 짜 줘"를 첫 질문으로 보내면 K1. 로그를 붙여 원인부터 묻고, 원인을 확인한 뒤 수정 방법을 묻고, 마지막에 테스트를 요청하면 통과. 로그를 보기 전에 "락 순서 바꿔 줘"부터 요청하면 K2.
- 비개발 예: "기획안 써 줘"를 첫 질문으로 보내면 K1. 설문에서 이탈 이유 정리 → 매출 자료에서 잠식 신호 찾기 → 결론과 근거 초안 순서로 나누면 통과. 자료를 확인하기 전에 "저가 요금제 출시가 맞다는 근거를 써 줘"부터 요청하면 K2.
- K3 예: "파일 열어 줘" → "첫 줄 읽어 줘" → "둘째 줄 읽어 줘"처럼 확인할 것 없는 일을 턴마다 쪼개면 걸림. "표 만들어 줘" → (표 확인) → "보고서 써 줘"는 통과.

**판정 예시 (한 요청만 보낸 경우)**
> 첨부한 파일 분석해서 표로 만들고 표로 만든 후 보고서 형태로 작성하고 맞춤법 다 맞추고 메일로 보내기 전에 워크시트에 올려 주고 그 다음에 메일 보내, 만약 메일이 안 보내지면 해결해 줘

| 코드 | 결과 | 근거 |
|---|---|---|
| K1 | -5 | 분석 → 표 → 보고서 → 업로드 → 발송이 앞 결과에 기대는데, 확인 지점 없이 한 번에 맡김. 분석이 틀리면 메일까지 그대로 이어짐 |
| K2 | -3 | "메일이 안 보내지면 해결해 줘"는 실패도 원인 확인도 하기 전에 해결부터 맡김. 본 작업은 "분석해서"로 시작해 순서가 맞으므로 메일 부분만 근거가 됨 |
| K3 | 통과 | 오히려 반대쪽(너무 큰 덩어리) 문제 |
| 합계 | -8 | 문제 분해력 2 / 10점 |

### 위임 판단력 (10점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| J0 | AI를 쓰지 않아 위임 판단을 볼 수 없음 (이 항목 0점) | -10 | 자동 |
| J1 | 과제의 핵심 판단(근본 원인 결정, 최종 결론과 추천안)을 AI에게 맡기고, 자기 판단이나 근거 없이 그대로 씀 | -4 | 판정 |
| J2 | 주어진 파일을 열어 보면 바로 아는 내용이나 단순 계산을 AI에게 여러 번 물음 | -3 | 판정 |
| J3 | AI에게 맡기기 좋은 반복 작업(비슷한 코드 여러 곳 수정, 표 정리, 초안 작성)을 직접 하느라 시간을 많이 씀 | -3 | 판정 |

- J1과 통제력 C1, C3의 구분: C1, C3는 "AI 답을 검증했는가", J1은 "판단 자체를 누가 내렸는가"를 본다. AI 답을 검증했어도 원인이나 결론을 고를 때 자기 근거가 없으면 J1에 걸린다. 겹쳐 감점되지 않게 판정 기준 문장에 예시를 넣어 구분한다.
- J3은 대화 기록만으로는 판정하기 어렵다. 파일 저장 기록(직접 편집한 양과 시간)을 채점 모델에 요약해 넘겨야 한다. 파일럿에서 판정이 흔들리면 빼고 J1, J2만 쓴다.

### AI를 쓰지 않은 응시

AI 활용력(U0), AI 통제력(C0), 문제 분해력(K0), 위임 판단력(J0)이 0점이다. 결과 도출력(30)과 성과 잠재력(15)만 받을 수 있어 최대 45점이다. 지금(재현성 포함 최대 45점)과 같다.

## 5. 재현성을 빼면 달라지는 것

| | 지금 | 초안 |
|---|---|---|
| 채점 비용 | 응시 1건 약 $0.025~0.03, R1 다시 실행(턴마다 5번)과 비교가 큰 몫 | R1 다시 실행과 비교 호출이 없어져 줄어듦 (정확한 값은 실험 채점으로 확인) |
| 채점 시간 | 한 건 약 40~60초 | 다시 실행을 기다리지 않아 짧아짐 |
| 점수 흔들림 | 같은 응시 재채점 범위 4~8점, R1 혼자 0~8점 | R1이 빠져 흔들림이 줄 것으로 예상. 새 판정 체크 7개가 늘어 다시 확인 필요 |
| 코드 | `Rubric`의 R0~R3, `ScoringService`의 다시 실행, 채점 툴과 배치의 R1 단계 | 재현성 관련 코드와 배치 2단계(R1 비교)를 걷어 내야 함 |

## 7. 검증 계획

1. 새 항목과 배점을 코드에 넣고(배점은 고정이라 코드 수정 필요), 채점 툴에서 새 판정 기준으로 프롬프트 버전을 만든다.
2. 샘플 응시 7건을 3번씩 채점해 점수 범위와 체크별 판정 엇갈림 비율을 지금 기준과 비교한다.
3. 일부러 만든 응시 2건으로 변별력을 확인한다: 통째로 맡긴 응시(K1, J1에 걸려야 함), 단계를 나눠 푼 응시(통과해야 함).
4. 엇갈림이 잦은 체크는 판정 기준 문장을 고치거나 뺀다.

- J3을 이번 파일럿에 넣을지
