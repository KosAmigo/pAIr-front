# pAIr 채점 기준표 (감점식, 총점 100점)

> 작성일: 2026-11-11
> 이 문서가 채점의 기준이다. 이전 문서 [재현성_AI결과도출력.md](재현성_AI결과도출력.md)의 하위 기준(R1~R3, D1~D5, 가중 평균 방식)은 이 문서로 대체한다.
> 구현: `backend/src/main/java/com/pair/scoring/Rubric.java`, `ScoringService.java`

## 1. 항목과 배점

프로그래머스 AI 역량평가 6개 항목 중 **AI 기초 이해력을 빼고** 5개 항목으로 구성한다. 재현성과 AI 통제력은 비중을 낮췄다.

| 항목 | 배점 | 무엇을 보나 | 기준 작성 |
|---|---|---|---|
| AI 활용력 | 25 | AI에게 맥락을 주고, 문제를 나눠 맡기고, 막히면 전략을 바꾸는가 | 초안 (담당자 검토 필요) |
| AI 통제력 | 15 | AI 결과를 검증하고, 틀리거나 위험한 제안을 걸러내는가 | 초안 (담당자 검토 필요) |
| 재현성 | 15 | 같은 지시로 같은 결과가 다시 나오고, 과정을 설명할 수 있는가 | 재현성 담당 |
| AI 결과 도출력 | 30 | 요구사항을 충족하는 결과물을 시간 안에 만들어 냈는가 | 도출력 담당 |
| 성과 잠재력 | 15 | 결과를 자기 말로 설명하고, 한계와 다음 개선을 아는가 | 초안 (담당자 검토 필요) |
| **합계** | **100** | | |

## 2. 채점 방식

- 각 항목은 **배점에서 시작해 체크 항목에 걸릴 때마다 감점**한다. 항목 점수는 0점 아래로 내려가지 않는다.
- 총점은 5개 항목 점수의 합이다.
- 체크 판정 방식은 두 가지다.
  - **자동**: 시스템이 기록(테스트 결과, 이벤트, 다시 실행 결과)으로 판정한다.
  - **판정**: 채점 모델(Claude Sonnet 5.5)이 대화 기록, 최종 파일, 후속 답변을 보고 "걸림 / 안 걸림"을 판정한다. 걸렸다고 할 때는 근거(대화 턴 `#T03`이나 파일 이름)를 반드시 대야 하고, 근거가 없으면 감점하지 않는다.
- 한 가지 행동을 두 항목에서 겹쳐 감점하지 않도록 체크 항목을 나눴다. 예: "AI 오답이 최종본에 남음"은 통제력(C2)에서만 감점하고, 도출력은 숨은 테스트와 체크리스트로만 본다.
- `개발`, `비개발` 표시는 해당 과제 유형에만 적용한다. 표시가 없으면 공통이다.

## 3. 감점표

### AI 활용력 (25점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| U0 | AI에게 한 번도 질문하지 않음 (이 항목 0점) | -25 | 자동 |
| U1 | 첫 질문에서 무엇을 하려는지(목표)를 밝히지 않음 | -4 | 판정 |
| U2 | 필요한 코드, 로그, 자료를 붙이지 않아 AI가 추측해서 답하게 함 | -5 | 판정 |
| U3 | 대부분의 질문에서 원하는 출력 형식이나 범위를 정하지 않음 | -3 | 판정 |
| U4 | 큰 문제를 한 번에 통째로 맡기고 단계를 나누지 않음 | -5 | 판정 |
| U5 | 막혔을 때 거의 같은 질문을 3번 이상 반복하고 전략을 바꾸지 않음 | -3 | 판정 |
| U6 | AI 답변을 받은 뒤 이어서 확인하거나 좁혀 묻는 질문이 없음 | -3 | 판정 |

### AI 통제력 (15점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| C1 | AI가 준 코드나 수치를 실행, 테스트, 자료 대조 없이 최종본에 넣음 | -5 | 판정 |
| C2 | AI의 오답이나 근거 없는 수치가 최종본에 남음 | -5 | 판정 |
| C3 | 증상만 가리는 제안(타임아웃 늘리기, 전체 잠금 등)이나 근거 없는 주장을 따져 보지 않고 받아들임 | -3 | 판정 |
| C4 | AI 답변의 근거나 이유를 한 번도 확인하지 않음 | -2 | 판정 |

### 재현성 (15점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| R1 | 핵심 AI 답변을 같은 요청으로 다시 실행하면 다른 해결책이 나옴 (다시 실행 중 다른 해결책 비율 × 8, 반올림) | 최대 -8 | 자동 |
| R2 | 핵심 지시가 앞 대화 없이는 뜻이 통하지 않음 ("그거 다시 해줘" 등) | -2 | 판정 |
| R3 | 후속 질문에서 설명한 절차가 실제 대화 기록과 다름 | -3 | 판정 |
| R4 | AI를 썼지만 최종 결과물에 AI 답변이 거의 남지 않아 같은 지시로 결과를 재현할 수 없음 | -2 | 자동 |

- R1은 AI 답변이 최종 결과물에 많이 남은 핵심 턴을 최대 3개 골라, 응시 때와 같은 회사, 모델, 요청 원문으로 턴마다 2번 다시 실행한다. 채점 모델이 원래 답변과 "같은 해결책"인지 판정한다.
- AI를 쓰지 않은 응시는 R1, R4를 적용하지 않는다(활용력 U0에서 이미 0점).

### AI 결과 도출력 (30점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| D0 | 제출 코드가 컴파일되지 않음 (이 항목 0점) `개발` | -30 | 자동 |
| D1 | 숨은 필수 테스트 실패 1개당 (4개) `개발` | 1개당 -5 | 자동 |
| D1 | 필수 체크리스트 미충족 1개당 (결론, 근거 3개, 잠식 효과, 리스크와 대응, 수치 정확성 중 앞 4개) `비개발` | 1개당 -5 | 판정 |
| D2 | 엣지 케이스 누락: 숨은 선택 테스트 실패 `개발` / 의향을 실제 전환율로 보정하지 않음 `비개발` | -2 | 자동 / 판정 |
| D3 | 수정을 확인하는 테스트를 추가하지 않음 `개발` / 근거 수치에 출처(어느 자료인지)를 밝히지 않음 `비개발` | -3 | 자동 / 판정 |
| D4 | NOTES.md에 원인과 근거를 쓰지 않음 `개발` / 결론과 근거가 서로 맞지 않음 `비개발` | -2 | 자동 / 판정 |
| D5 | 첫 유효 결과가 30분을 넘김 (-2) / 끝까지 도달하지 못함 (-4) | 최대 -4 | 자동 |

- 첫 유효 결과: 개발은 "테스트를 추가하고 전부 통과한 첫 실행", 비개발은 "필수 제목(결론, 근거, 리스크)을 모두 채운 첫 저장".
- 비개발의 "수치 정확성"(체크리스트 5번)은 통제력 C2에서 본다.

### 성과 잠재력 (15점)

| 코드 | 체크 항목 | 감점 | 판정 |
|---|---|---|---|
| P1 | 후속 질문 답변이 근거 없이 한두 마디에 그침 | -5 | 판정 |
| P2 | 채택하지 않은 AI 제안과 그 이유를 설명하지 못함 | -4 | 판정 |
| P3 | 오류나 테스트 실패에서 원인을 확인하지 않고 같은 시도를 반복함 | -3 | 판정 |
| P4 | 결과의 한계나 남은 위험을 전혀 언급하지 않음 (후속 답변, NOTES.md, 기획안) | -3 | 판정 |

## 4. 리포트에 보이는 것

- 총점 `NN / 100`과 항목별 `점수 / 배점`
- 항목마다 체크 항목 표: 걸린 항목은 감점과 근거(대화 턴 링크)와 한 줄 이유, 안 걸린 항목은 "통과"
- 다시 실행 판정(R1), 숨은 테스트 결과(개발), 토큰 사용량

## 5. 이전 방식과 달라진 점

| | 이전 | 지금 |
|---|---|---|
| 항목 | 재현성, AI 결과 도출력 2개만 채점 (6개 체계) | 5개 항목 모두 채점, 총점 100 |
| 점수 계산 | 하위 기준마다 0~100점을 매겨 가중 평균 | 배점에서 체크 항목별 감점 |
| 채점 모델 역할 | 하위 기준 점수(0~100)를 직접 매김 | 체크 항목이 "걸림 / 안 걸림"인지 근거와 함께 판정 |

감점식으로 바꾸면 채점 모델이 숫자를 고르지 않고 예/아니오만 판정하므로, 같은 응시를 다시 채점했을 때 점수가 덜 흔들리고 사람이 결과를 검토하기도 쉽다.

## 6. 남은 일
- 활용력, 통제력, 성과 잠재력 체크 항목은 초안이다. 각 담당자가 검토한다.
- 감점 크기는 파일럿 응시 결과를 보고 한 번 조정한다.
- 파일럿 채점 시트(Google 스프레드시트)는 아직 이전 방식(R1~R3, D1~D5)이다. 감점표에 맞춰 다시 만들어야 한다.
