# pAIr 요구사항 명세서

| 항목 | 내용 |
|---|---|
| 근거 | ERD DDL 최신본(기업 계정 분리 버전, PostgreSQL) |
| 우선순위 | 상(필수) / 중(중요) / 하(선택) |
| 작성 양식 | 요구사항마다 설명 · 입력 · 처리 · 출력 · 예외 · 관련 테이블 |

## 1. 개요

### 1.1 목적
pAIr는 응시자가 AI 어시스턴트와 함께 실무형 과제(DEV/BIZ)를 수행하게 하고, 수행 과정(대화·파일·작업 기록)과 문항 답변을 LLM 판정 모델로 채점해 AI 협업 역량을 평가하는 서비스이다.

### 1.2 범위
- 개인 회원의 자가진단 응시(SELF)
- 기업이 여는 감독형 실전 시험 회차(LIVE)
- 과제·문항·루브릭·채점 프롬프트 관리(관리자)
- 루브릭과 다중 판정 모델을 쓰는 자동 채점

### 1.3 액터
| 액터 | 계정 테이블 | 설명 |
|---|---|---|
| 개인 회원 | users (role=USER) | 과제를 자가진단으로 응시하고 결과를 본다 |
| 관리자 | users (role=ADMIN) | 과제·문항·루브릭·프롬프트를 관리하고 기업 가입을 승인한다 |
| 기업 회원 | companies | 별도 계정으로 로그인해 실전 회차를 열고 응시자를 관리한다 |
| 초대 응시자 | exam_participants | 메일 링크로 실전 회차에 입장한다 |
| 채점 시스템 | — | 제출된 응시를 판정 모델로 채점한다 |

## 2. 기능 요구사항

### 2.1 계정

#### FR-ACC-01 개인 회원가입 (상)
- **설명:** 개인이 이메일로 회원가입한다.
- **입력:** 이메일, 비밀번호, 이름
- **처리:** 이메일 중복을 검사하고, 비밀번호를 BCrypt로 해시한다. role=USER, member_status=ACTIVE로 저장한다.
- **출력:** 가입 완료, 로그인 화면으로 이동
- **예외:** 이메일 중복이면 "이미 가입된 이메일"을 안내한다.
- **관련 테이블:** users

#### FR-ACC-02 개인 로그인 (상)
- **설명:** 이메일과 비밀번호로 로그인한다.
- **처리:** 해시를 비교하고, member_status가 ACTIVE인지 확인한다.
- **예외:** 비밀번호가 틀렸거나 WITHDRAWN·PENDING 상태이면 로그인할 수 없다.
- **관련 테이블:** users

#### FR-ACC-03 회원 탈퇴 (중)
- **처리:** member_status를 WITHDRAWN으로 바꾼다. 응시 기록은 보존한다.
- **관련 테이블:** users

#### FR-ACC-04 기업 회원가입 (상)
- **설명:** 기업이 개인과 분리된 기업 계정을 만든다.
- **입력:** 로그인 이메일, 비밀번호, 담당자 이름, 회사 이름, 사업자등록번호
- **처리:** 이메일과 사업자등록번호의 중복을 검사하고, 비밀번호를 BCrypt로 해시한다. company_status=승인대기로 저장한다.
- **출력:** "승인 후 이용 가능" 안내
- **예외:** 이메일이나 사업자등록번호가 중복되면 가입할 수 없다.
- **관련 테이블:** companies

#### FR-ACC-05 기업 가입 승인 (상)
- **설명:** 관리자가 승인대기 기업을 검토해 정상으로 바꾼다.
- **처리:** company_status를 승인대기에서 정상으로 바꾼다.
- **예외:** 승인 전 기업은 로그인할 수는 있지만 회차를 열 수 없다.
- **관련 테이블:** companies

#### FR-ACC-06 기업 로그인 (상)
- **설명:** 기업 계정 이메일과 비밀번호로 로그인하며, 개인 로그인과 별도로 처리한다.
- **관련 테이블:** companies

### 2.2 과제 관리 (관리자)

#### FR-TSK-01 과제 등록·수정 (상)
- **입력:** 코드, 제목, 한 줄 소개, 상세 설명, 요구사항, 직군(DEV/BIZ), 과제 형태, 난이도, 제한 시간(분), 상태
- **처리:** 코드가 중복되는지 검사한다. 상태 기본값은 OPEN이다.
- **예외:** 코드가 중복되면 저장할 수 없다.
- **관련 테이블:** tasks

#### FR-TSK-02 과제 공개 상태 (상)
- **처리:** OPEN 과제는 목록에 보이고 응시할 수 있다. CLOSE 과제는 응시할 수 없다. HIDDEN 과제는 목록에 보이지 않는다.
- **관련 테이블:** tasks

#### FR-TSK-03 과제 파일 등록 (상)
- **입력:** 파일 경로, 파일(텍스트 또는 바이너리), 공개 여부(VISIBLE/HIDDEN), 읽기 전용 여부
- **처리:** 텍스트 파일은 내용을 DB에 저장하고, PDF 같은 바이너리 파일은 스토리지에 올린 뒤 저장 위치를 기록한다. 파일 형식과 크기도 기록한다.
- **예외:** 같은 과제에 같은 경로가 있으면 등록할 수 없다.
- **관련 테이블:** task_files

#### FR-TSK-04 문서 텍스트 추출과 임베딩 (중)
- **처리:** 문서 파일을 페이지별 텍스트로 추출한 뒤 조각으로 나누고, 토큰 수와 임베딩 벡터를 저장한다.
- **출력:** 채점할 때 코사인 유사도로 검색할 수 있는 조각
- **관련 테이블:** document_pages, document_chunks

### 2.3 문항 관리 (관리자)

#### FR-QST-01 문항 등록 (상)
- **입력:** 단계(TASK/FOLLOWUP), 유형(SINGLE/MULTI/SHORT/ESSAY), 순서, 문제 내용, 배점, 서술형 채점 기준
- **처리:** 후속 질문(FOLLOWUP)은 배점 없이 저장한다. 문항은 삭제하지 않고 사용 여부로 비활성화한다.
- **관련 테이블:** task_questions

#### FR-QST-02 객관식 보기 (상)
- **입력:** 보기 순서, 보기 내용, 정답 여부
- **예외:** SINGLE 문항은 정답이 정확히 1개여야 한다(서비스 코드에서 검사).
- **관련 테이블:** question_choices

#### FR-QST-03 단답형 인정 답안 (상)
- **처리:** 문항 하나에 인정 답안을 여러 개 등록할 수 있다.
- **예외:** 같은 문항에 같은 답안을 두 번 등록할 수 없다.
- **관련 테이블:** short_answer_keys

#### FR-QST-04 문항 근거 문서 (하)
- **처리:** 문항이 근거로 삼는 과제 파일과 페이지, 출제 메모를 기록한다.
- **관련 테이블:** question_sources

### 2.4 응시

#### FR-ATT-01 응시 시작 (상)
- **입력:** 과제, 모드(SELF/LIVE), 어시스턴트 모델
- **처리:** 응시를 만들고 시작 시각을 기록한다. 자가진단은 같은 과제를 여러 번 응시할 수 있다. 응시를 시작할 때 과제 파일 중 VISIBLE 파일을 작업 파일로 복사한다.
- **예외:** OPEN이 아닌 과제는 자가진단으로 응시할 수 없다.
- **관련 테이블:** attempts, attempt_files

#### FR-ATT-02 작업 파일 편집 (상)
- **처리:** 파일을 경로 단위로 저장하고 수정 시각을 갱신한다. 읽기 전용 파일은 수정할 수 없다.
- **관련 테이블:** attempt_files

#### FR-ATT-03 AI 대화 (상)
- **처리:** 사용자 질문과 AI 응답을 턴 번호 순서로 저장한다. AI 턴에는 모델과 입력·출력 토큰 수를 기록한다.
- **예외:** 같은 응시 안에서 턴 번호가 중복되면 저장할 수 없다.
- **관련 테이블:** chat_turns

#### FR-ATT-04 대화 첨부 (중)
- **입력:** 출처(TASK_FILE/ATTEMPT_FILE), 파일, 페이지 범위
- **처리:** 실제로 AI에 보낸 내용을 저장한다. 출처가 TASK_FILE이면 과제 파일 ID가 필수다.
- **관련 테이블:** chat_attachments

#### FR-ATT-05 작업 기록 (상)
- **처리:** SAVE, BUILD, RUN, AI_EDIT, SUBMIT 이벤트를 상세 내용(JSON)과 함께 기록한다.
- **관련 테이블:** attempt_events

#### FR-ATT-06 체크포인트와 롤백 (중)
- **처리:** 특정 대화 턴 시점의 파일 전체를 체크포인트로 저장한다. 체크포인트에서 새 응시를 분기할 수 있고, 분기한 응시에는 출발 체크포인트를 기록한다.
- **관련 테이블:** checkpoints, checkpoint_files, attempts

#### FR-ATT-07 문항 답변 (상)
- **처리:**
  - 단답형·서술형은 응시당 문항 하나에 답 하나를 저장한다.
  - 객관식은 선택한 보기를 저장하며, 보기는 해당 문항의 것이어야 한다.
  - SINGLE은 보기를 하나만, MULTI는 여러 개를 고를 수 있다.
- **관련 테이블:** text_answers, choice_answers

#### FR-ATT-08 제출과 후속 질문 (상)
- **처리:** 제출하면 제출 시각을 기록하고 후속 질문(FOLLOWUP)을 보여준다. 후속 질문에 모두 답하면 완료 시각을 기록하고 채점을 요청한다.
- **관련 테이블:** attempts

### 2.5 실전 시험 (기업 회원)

#### FR-EXM-01 회차 생성 (상)
- **입력:** 회차 이름, 시작·종료 시각, 감독 사용 여부, 첨부 파일
- **처리:** 회차를 연 기업을 기록한다. 입장 코드는 중복되지 않게 발급한다.
- **예외:**
  - 종료 시각이 시작 시각보다 늦지 않으면 저장할 수 없다.
  - 승인대기 기업은 회차를 만들 수 없다.
- **관련 테이블:** exam_sessions

#### FR-EXM-02 회차 과제 구성 (상)
- **처리:** 한 회차에 과제를 여러 개 묶는다.
- **예외:** 같은 회차에 같은 과제를 두 번 넣을 수 없다.
- **관련 테이블:** task_set

#### FR-EXM-03 응시자 초대 (상)
- **입력:** 응시자 이메일, 이름(한 명씩 또는 여러 명)
- **처리:** 응시자마다 추측할 수 없는 입장 토큰을 만들어 초대 메일을 보내고, 초대 시각을 기록한다.
- **예외:** 같은 회차에 같은 이메일을 두 번 초대할 수 없다.
- **관련 테이블:** exam_participants

#### FR-EXM-04 입장 (상)
- **처리:** 토큰을 확인하고 입장 시각을 기록한 뒤, LIVE 모드로 응시를 만들어 연결한다. 대상자 1명은 응시 1개만 가진다.
- **예외:**
  - 토큰이 유효하지 않으면 입장할 수 없다.
  - 회차 시작 전이거나 종료 후에는 입장할 수 없다.
- **관련 테이블:** exam_participants, attempts

#### FR-EXM-05 회차 시간 통제 (상)
- **처리:** 종료 시각이 되면 제출하지 않은 응시를 자동으로 제출한다.
- **관련 테이블:** exam_sessions, attempts

#### FR-EXM-06 회차 결과 조회 (상)
- **처리:** 기업 회원은 자기 회차의 응시자별 점수, 감점 근거, 감독 이벤트를 조회한다.
- **관련 테이블:** exam_participants, scorings, proctor_events

### 2.6 감독

#### FR-PRC-01 감독 동의와 환경 점검 (상)
- **처리:** 감독이 켜진 회차는 응시 전에 동의서 버전과 환경 점검 결과(카메라, 브라우저, 전체화면)를 응시당 한 번 저장한다.
- **예외:** 동의하지 않거나 환경 점검을 통과하지 못하면 응시할 수 없다.
- **관련 테이블:** proctor_consents

#### FR-PRC-02 이상 행동 기록 (상)
- **처리:** 다음 이벤트를 시작 시각, 지속 시간(0 이상), 확신도(0~1), 상세 내용과 함께 저장한다.
  - TAB_HIDDEN(탭 숨김), WINDOW_BLUR(창 이탈), PASTE(붙여넣기), FULLSCREEN_EXIT(전체화면 해제)
  - NO_FACE(얼굴 없음), MULTI_FACE(여러 얼굴), HEAD_TURN(고개 돌림), PHONE(휴대폰 감지)
- **관련 테이블:** proctor_events

#### FR-PRC-03 스냅샷 보관과 삭제 (중)
- **처리:** 스냅샷 저장 위치를 기록하고, 보관 기간이 지나면 파일을 삭제한 뒤 삭제 시각을 남긴다.
- **관련 테이블:** proctor_events

### 2.7 채점

#### FR-SCR-01 루브릭 관리 (상)
- **처리:** 역량 항목(키, 이름, 배점, 순서)과 그 아래 체크 항목(코드, 적용 직군 ALL/DEV/BIZ, 판정 방식 AUTO/JUDGE, 감점, 내용)을 관리한다.
- **예외:** 같은 직군에 같은 코드를 두 번 쓸 수 없다.
- **관련 테이블:** rubric_items, rubric_checks

#### FR-SCR-02 채점 프롬프트 버전 (상)
- **처리:** 공통 채점 규칙과 체크별 판정 기준 문장을 버전 단위로 저장하고, 바탕 버전을 기록한다. 실제 채점에 쓰는 버전을 활성화한다.
- **관련 테이블:** prompt_versions, prompt_check_hints

#### FR-SCR-03 채점 실행 (상)
- **처리:**
  1. 채점 실행을 만든다(활성 버전 사용, 시작 시각과 상태 기록).
  2. 판정 모델을 여러 번 호출하고, 호출마다 토큰 수를 기록한다.
  3. 체크마다 모델별 판정(위반 여부, 미충족 개수, 이유, 근거)을 저장한다.
  4. 모델별 판정을 체크 결과(DEDUCTED/PASSED/SPLIT/NO_EVIDENCE/SKIPPED)와 감점으로 합친다.
- **예외:** 실패하면 오류 내용을 기록한다. 한 응시를 다시 채점할 수 있다.
- **관련 테이블:** scorings, judge_calls, judge_verdicts, verdict_evidences, check_results

#### FR-SCR-04 문항 채점 (상)
- **처리:** 객관식·단답형은 코드로 비교해 채점하고(AUTO), 서술형은 판정 모델이 채점 기준으로 채점한다(JUDGE). 문항별로 점수와 이유를 저장한다.
- **관련 테이블:** question_results

#### FR-SCR-05 결과 리포트 (상)
- **처리:** 역량 항목별 점수, 감점된 체크, 판정 근거(대화 턴, 파일, 문항)를 보여준다.
- **관련 테이블:** 채점 관련 테이블 전체

## 3. 비기능 요구사항
| ID | 분류 | 요구사항 | 우선순위 |

## 4. 데이터 무결성 규칙
| ID | 규칙 | 구현 위치 |
|---|---|---|
| DR-01 | 글 답변은 SHORT/ESSAY 문항, 객관식 답변은 SINGLE/MULTI 문항에만 연결된다. | 복합 FK + CHECK |
| DR-02 | 선택한 보기는 해당 문항의 보기여야 한다. | 복합 FK (choice_id, question_id) |
| DR-03 | TASK_FILE 첨부는 과제 파일 ID가 있어야 한다. | CHECK |
| DR-04 | 회차 종료 시각은 시작 시각보다 늦어야 한다. | CHECK |
| DR-05 | 감독 이벤트의 지속 시간은 0 이상, 확신도는 0~1이다. | CHECK |
| DR-06 | 실전 응시의 과제는 그 회차의 과제 묶음에 있는 과제여야 한다. | 서비스 코드 |
