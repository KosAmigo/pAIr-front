# pAIr 기획 결정 사항

> 2026-11-18 정리. 애매했던 기획 요소를 질문으로 확정한 결과다. 구현과 ERD는 이 문서를 기준으로 맞춘다.
> **ERD 반영** 칸: ✅ 반영됨 · ⬜ 아직 반영 안 됨(후속 작업) · — DB 변경 없음

## 1. 실전 시험 (B2B)

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 응시자 가입 | 회원가입 없이 응시. 기록은 기업 쪽에만 남고 응시자의 "내 기록"에는 나오지 않는다 | ✅ attempts.user_id는 자가진단만 |
| 입장 방법 | **메일로 받은 개인별 입장 링크로만** 입장. 회차 공용 입장 코드는 없다. 링크는 기업이 등록한 대상자에게만 나가므로 명단에 없는 사람은 들어올 수 없다 | ✅ entry_code 삭제 |
| 링크 토큰 | 추측할 수 없는 무작위 값(`SecureRandom` 32바이트, Base64URL). **DB에는 SHA-256 해시만 저장**한다. DB가 유출돼도 링크를 만들 수 없다. 메일을 다시 보낼 때는 토큰을 새로 만든다(이전 링크는 무효) | ✅ invite_token_hash |
| 토큰 만료 | 따로 만료 시각 없음. 회차 종료(`ends_at`)가 지나면 쓸 수 없다 | — |
| 메일 발송 | 대상자 등록 즉시 1번, 시작 24시간 전 알림 1번 | ✅ invited_at, reminded_at |
| 대상자 등록 | 회차 만들기 화면에서, **사이트가 제공하는 양식에 맞춘 CSV 업로드**(이름, 이메일). 업로드 전에 중복·형식 오류를 미리 보여 준다 | — |
| 회차 과제 | 한 회차에 과제 여러 개. 응시자는 회차 시간 안에서 **과제를 자유롭게 오가며** 푼다 | ✅ exam_session_tasks |
| 시간 | 과제별 시간 없이 **회차 전체(시작~종료)**로 본다 | ✅ |
| 제출 | **과제별로 제출**한다. 종료 시각에 남은 과제는 자동 제출. 제출한 과제부터 채점을 시작한다 | — (attempts가 과제별 1건) |
| 후속 질문 | 실전에도 **과제마다** 후속 질문(설명 서술형)을 둔다. 회차 시간 안에 포함 | — |
| 감독 동의 | 대상자마다 회차당 1번 | ✅ proctor_consents PK = participant_id |
| 끊김·결시 | 종료 전이면 **같은 링크로 다시 들어와 이어서** 푼다. 끊긴 시간은 보전하지 않는다. 결시자는 새 회차에 다시 초대한다 | — |
| 결과 공개 | 응시자에게는 **보여 주지 않는다**(제출 완료 안내만). 결과는 기업만 본다 | — |
| 기업이 보는 결과 | 대상자별 리포트(6개 역량 점수, 근거 턴, 감독 주의 구간), 회차 안 **순위와 역량별 분포** | — (조회로 계산) |
| 회차 수정·취소 | **시작 전까지만** 시간·과제·대상자 수정과 취소 가능(변경 시 대상자에게 메일). 시작 후에는 바꿀 수 없다 | ✅ exam_sessions.canceled_at(시작 전만) |
| 보관 기간 | 감독 스냅샷은 회차 종료 **30일** 뒤 자동 삭제(`snapshot_deleted_at`). 응시·채점 기록은 **1년** | ✅ snapshot_deleted_at |
| 판정 | 감독 이벤트는 자동 탈락이 아니라 담당자가 확인(OK/SUSPECT)하는 기록 | ✅ |

## 2. 과제

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 과제 용도 | 과제마다 **용도 하나**: 자가진단용(`SELF`) 또는 기업용(`LIVE`). 기업용 과제는 자가진단 목록에 절대 나오지 않아 문제가 새지 않는다 | ✅ tasks.usage + 응시 모드와 복합 FK |
| 기업용 과제 | 관리자가 **아주 많이** 만들어 두고, 기업 담당자가 그중에서 골라 회차에 건다 | ✅ exam_session_tasks 복합 FK |
| 과제 공유 | 기업용 과제는 **모든 기업이 공유**한다(한 기업 전용 아님) | — (tasks.company_id 두지 않음) |
| 상태 | `OPEN` 공개·응시 가능 / `CLOSED` 목록에만 보이고 응시 막힘 / `HIDDEN` 숨김(초안·검수 대기, 기본값). 회차에는 `OPEN`만 걸 수 있다(2026-11-18 팀 DDL과 머지) | ✅ |
| AI 문제 생성 | 관리자가 **글로만 정의**(직군, 난이도, 주제, 함정 등 폼 입력)하면 AI가 생성해 `HIDDEN`으로 저장, 관리자가 검토 후 공개. 참고 파일 업로드는 없다. 생성 기록 테이블은 두지 않는다 | ✅ |
| 자가진단 과제 선택 | 목록에서 직군·난이도·시간으로 걸러 **직접 고른다**. 같은 과제 재응시 가능 | — |

## 3. 자가진단과 크레딧

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 과금 방식 | **크레딧**. 크레딧이 있어야 응시를 시작할 수 있다 | ✅ credit_ledger |
| 크레딧 얻기 | **가입 시 무료 지급** + **크레딧 단품 구매** | ✅ SIGNUP, PURCHASE |
| 크레딧 쓰기 | **응시 시작**(채점 1회 비용 포함), **롤백 1회**, **AI 채팅 턴 1회**마다 정해진 양을 쓴다. 양은 설정값으로 둔다 | ✅ ATTEMPT_START, ROLLBACK, CHAT_TURN |
| 재응시 | 같은 과제를 다시 풀어도 **새 응시와 같은** 크레딧 | — |
| 부족할 때 | 응시 중 크레딧이 바닥나면 **AI 채팅만 막는다**. 코드 편집과 제출은 된다. 채점은 응시 시작 때 이미 냈으므로 항상 된다 | — |
| 기록 | 적립·차감 한 건마다 **원장 행**(사유, 응시 ID, 양, 시각)으로 남긴다. 잔액은 원장 합계(필요하면 회원에 캐시). 동시에 여러 번 차감돼도 음수가 되지 않게 잠금 처리 | ✅ balance_after >= 0 |
| 롤백 횟수 | 제한 없음(크레딧으로만 제한) | — |
| 결제 | 크레딧 구매 결제는 테스트 결제(결제 대행사 테스트 모드)로 구현 | ✅ credit_purchases |
| 리포트 공유 | 본인이 켜면 **읽기 전용 공유 링크**가 생기고 언제든 끌 수 있다(이력서에 첨부 가능) | ✅ attempts.share_token_hash |
| 기업 열람 | 기업은 대상자의 자가진단 기록을 **볼 수 없다**. 자가진단과 실전은 완전히 분리. 본인이 공유 링크를 직접 주는 것만 가능 | — |
| 회원 상태 | `PENDING` 이메일 인증 전 → `ACTIVE` 정상 → `WITHDRAWN` 탈퇴 | ✅ users.member_status |
| 탈퇴 | **개인정보만 지운다**(이메일·이름 익명화). 응시·채점 기록과 크레딧 원장은 통계와 정산을 위해 남긴다 | ✅ users.deleted_at + 익명값 |

## 4. 기업 계정

| 항목 | 결정 | ERD 반영 |
|---|---|---|
| 가입 흐름 | **도입 문의 → 관리자 승인 → 초대**. 기업이 문의 폼을 내면 관리자가 승인하면서 회사를 등록하고 담당자에게 초대 메일을 보낸다. **초대 링크로만** 담당자 계정을 만들 수 있다(자체 가입 없음) | ✅ company_inquiries, company_invites |
| 담당자 수 | 한 회사에 **여러 명**. 관리자가 같은 회사에 담당자를 추가로 초대할 수 있고, 모두 그 회사의 회차를 함께 본다 | ✅ users.company_id |
| 기업 권한 | 기업 회원은 두 가지: **`MANAGER`**(회차 만들기, 기업용 과제 고르기, 대상자 등록, 결과 보기, 감독관 초대, **감독도 가능**)와 **`PROCTOR`**(감독관: 감독 화면과 감독 이벤트 판단만). 관리자가 첫 매니저를 초대하고, 매니저가 자기 회사 감독관을 초대한다 | ✅ users.role, company_invites.role |
| 회사 데이터 분리 | 담당자는 자기 회사 회차·대상자·결과만 본다 | ✅ |
| 기업 과금 | **기획만** 하고 구현하지 않는다(예: 응시자 1명당 과금). 승인된 기업은 무료로 쓴다 | — |

## 5. 후속 작업

ERD 반영은 끝났다(2026-11-18, 테이블 38개 · 외래 키 59개). 남은 것은 구현이다.
1. 프론트 콘솔의 회차 데이터를 과제 여러 개 구조로 바꾸기, 회차 만들기에 CSV 업로드(양식 내려받기 포함)
2. 자가진단 과제 목록은 `usage = 'SELF' AND status = 'OPEN'`만, 회차 과제 고르기는 `usage = 'LIVE' AND status = 'OPEN'`만
3. 크레딧: 잔액 표시, 차감(회원 행 잠금), 테스트 결제, 부족하면 채팅만 막기
4. 리포트 공유 링크 켜기·끄기, 공유 링크 보기 화면
5. 기업 도입 문의 폼, 관리자 승인·초대, 초대 링크 가입
6. 메일: 입장 링크(등록 즉시), 하루 전 알림 배치, 회차 변경·취소 안내
7. 스냅샷 30일 삭제 배치, 기록 1년 보관 정책
